# 媒体按日期与地点整理设计

## 目标

在现有文件与文件夹整理工具中增加媒体整理流程。照片和视频根据真实拍摄时间、国家、城市和媒体类型生成目标目录；普通文件与文件夹继续使用现有 Jev 标签分类。

目标路径固定为：

```text
<父目录>/<年>/<月>/<国家>/<城市>/<照片或视频>/<原文件名>
```

例如：

```text
Downloads/2026/09/中国/上海/照片/IMG_2048.HEIC
Downloads/2026/09/中国/上海/视频/IMG_2049.MOV
```

## 支持范围

- 照片：JPEG、HEIC、PNG、TIFF，以及当前 macOS ImageIO 能解析元数据的 RAW 格式。
- 视频：MOV、MP4、M4V。
- Live Photo：根据媒体元数据中的配对标识关联照片与 MOV，作为一个逻辑项目处理，两部分一起移动到 `照片` 目录。
- 普通文件和普通文件夹：保留现有“工作、学习、生活、影音、软件、其他”分类流程。
- 每次扫描最多保留现有的 500 个逻辑项目限制；一个 Live Photo 文件对计为一个逻辑项目。

不支持 Photos.app 照片图库包内部整理。用户需要选择普通文件系统目录；图库包作为普通目录跳过，避免破坏照片图库数据库。

## 架构

新增一个随项目构建的 macOS 原生元数据助手。Node.js 服务以结构化 JSON 调用助手：

- ImageIO 读取照片的拍摄日期、时区、GPS 和 Live Photo 配对标识。
- AVFoundation 读取视频的创建日期、时区、位置和 Live Photo 配对标识。
- Core Location 的反向地理编码将 GPS 坐标转换成国家和城市。

Node.js 负责扫描调度、缓存、规则计算、预览数据、移动日志和撤销。原生助手只读媒体元数据，不移动文件。Jev 不参与日期或地点推断，也不会收到媒体内容、缩略图或 GPS 坐标；它继续服务普通项目的固定标签选择。

元数据助手仅在 macOS 可用。其他系统继续支持现有通用分类，并在媒体整理入口说明需要 macOS，而不是静默使用不可靠的替代结果。

## 元数据规则

### 拍摄时间

按以下优先级选取：

1. 照片 EXIF `DateTimeOriginal` 及其 offset 字段，或视频 QuickTime 创建日期。
2. 文件名中的明确日期与时间，例如 `IMG_20260921_143000.jpg`。只接受经过严格解析且日历有效的模式。
3. 文件系统创建时间，并在预览中标记 `inferredDate: true`。
4. 如果以上均不可用，使用路径 `未知日期/未知月份`，不以扫描时间代替拍摄时间。

月份使用两位数字。元数据自带时区时按该时区确定年月；没有时区时使用运行工具的 Mac 当前时区，并在预览中标记时间为推断值。不会根据文件当前所在目录猜测日期。

### 国家与城市

存在有效 GPS 时，通过 Core Location 反向地理编码，优先输出简体中文国家和城市名称。目录层级为 `国家/城市`。

不存在 GPS 时使用 `未知国家/未知城市`。反向地理编码失败或离线时保留坐标和 `locationStatus: unresolved`，界面允许用户填写国家与城市后再移动；程序不会让 Jev 根据文件名猜地点。

国家和城市目录名会去除首尾空白，并把 `/`、NUL 等文件系统不允许或有路径语义的字符替换为安全字符。空值统一回退到未知国家或未知城市。

### 媒体类型

- 普通照片进入 `照片`。
- 普通视频进入 `视频`。
- Live Photo 的照片和配套视频一起进入 `照片`，界面显示为 `Live Photo · 2 个文件`。

## 地理编码与隐私

媒体文件和缩略图不上传。读取 EXIF、QuickTime 元数据和 Live Photo 配对信息都在本机完成。

Core Location 反向地理编码可能联网并将坐标发送给 Apple。首次使用地点解析前，界面明确显示这一边界。用户可以关闭在线地点解析；关闭后，有 GPS 的项目显示坐标并等待手动输入国家和城市。

为控制查询量，地理编码按约 1 公里粒度的坐标键缓存。缓存保存在项目本地数据目录，仅保存坐标键、国家、城市、更新时间和解析状态，不保存文件路径。成功结果长期复用；临时失败结果设置短期失效时间，以便之后重试。

## 扫描与界面

扫描响应中的媒体逻辑项目增加：

```json
{
  "type": "media",
  "mediaType": "photo",
  "members": ["IMG_2048.HEIC"],
  "capturedAt": "2026-09-21T14:30:00+08:00",
  "dateSource": "embedded",
  "country": "中国",
  "city": "上海",
  "locationStatus": "resolved",
  "targetSegments": ["2026", "09", "中国", "上海", "照片"]
}
```

预览表显示原文件名、媒体类型、拍摄时间、时间来源、国家、城市和完整目标路径。用户可以调整年份、月份、国家、城市和照片/视频类型；所有修改只更新预览，直到用户明确执行整理。

筛选增加照片、视频、Live Photo、地点待确认和时间待确认。普通项目仍显示现有标签控件。媒体项目不显示 Jev 置信度，因为其路径来自元数据和显式回退规则；相应位置显示“元数据”或“推断时间”。

## 移动、冲突与撤销

媒体目标目录允许多层相对路径，但每一段都由后端根据扫描结果和经过校验的用户修改生成。客户端不能提交任意目标路径。后端重新验证源项目身份、媒体成员、父目录身份和每个目标目录，拒绝路径穿越和符号链接。

普通媒体文件沿用写前日志：先持久化操作，再使用同一文件系统内的 rename 移动。目标存在时跳过，不覆盖、不自动改名。

Live Photo 是一个原子逻辑组：

1. 移动前验证照片和视频仍是扫描时的同一文件。
2. 任一目标冲突时整组跳过。
3. 日志先记录组内所有成员及身份。
4. 若进程在移动组的中途终止，重启恢复会识别每个成员的当前位置，并将批次标记为需要恢复；不会把半组状态报告为成功。
5. 撤销时先验证所有原位置均空闲，再按反向顺序移动；任一原位置冲突时整组保持在目标位置并报告冲突。

创建出的空目录在撤销后保留，与现有行为一致。旧操作日志继续按原格式读取和撤销。

## 错误处理

- 元数据无法解析：保留项目，按文件名或文件系统创建时间回退，并在预览显示来源。
- 地理编码失败：不阻塞扫描，标记地点待确认。
- 媒体格式不受支持：作为普通文件进入现有分类流程。
- 文件在扫描后被替换、改名或删除：执行时跳过并要求重新扫描。
- 目标冲突：跳过且不覆盖。
- 跨设备移动：报错，不使用复制后删除。
- 原生助手崩溃或输出无效 JSON：该媒体项目标记元数据失败，其他项目继续扫描。

## 测试与验收

自动化测试使用临时目录和不含私人内容的小型测试媒体，覆盖：

- JPEG/HEIC 的 EXIF 日期、时区和 GPS。
- MOV/MP4 的 QuickTime 日期和位置。
- 文件名日期回退、文件创建时间回退和未知日期。
- GPS 缺失、地理编码成功、离线失败、缓存命中和手动国家/城市。
- 中文国家/城市、路径字符清洗和年月边界。
- Live Photo 配对、一起移动、任一目标冲突、移动中断恢复和整组撤销。
- 普通照片与视频移动后字节完全不变。
- 旧日志兼容以及普通文件、文件夹的现有 Jev 分类回归。
- 浏览器中混合显示普通项目与媒体项目，修改预览后执行并撤销。

验收示例：扫描一张带有 2026-09 上海 GPS 的 HEIC 和配套 Live Photo MOV 后，界面只显示一个 Live Photo 项目；确认后两个源文件都位于 `2026/09/中国/上海/照片/`，撤销后都回到原位置且哈希值不变。
